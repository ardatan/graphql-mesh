`stitchSchemas` stays generic: optional `onStitchedSchema` runs immediately before shared backbone root proxies install. No federation filter inside stitch. No `overrideLabels` / `handleProgressiveOverride` on stitch or attach options — progressive override uses per-request active labels on context only (no `schema.extensions` stash / `readProgressiveOverride`).

Federation `getStitchingOptionsFromSupergraphSdl` sets stitch `onStitchedSchema` to `filterInternalFieldsAndTypes` then the user hook; `getStitchedSchemaFromSupergraphSdl` is `stitchSchemas(opts)`. Proxies attach once to the public schema. No snapshot/mark of late root overrides as `localFields` — no Mesh/Hive-gateway production caller replaces Query/Mutation resolvers that way. External post-stitch `mapSchema` is unsupported. Root proxy marks use module WeakSets; Island originals use a field→resolve WeakMap. Root proxies memoize `document` via `memoize2(operation, fragments)`. `installRootProxyingResolvers` is the single install API (root proxies call `backboneExecutor(request)` with no schema arg). `getBackboneExecutorBySchema` is `memoize1(schema => request => backboneExecutor(request, schema))` — does not mutate `info.schema`. `buildStitchPlan(schema, operation, fragments, activeLabels)` — caller extracts op/fragments. Plan cache is WeakMap(schema→document→Map) keyed by `` `${operationName}::${sortedLabels}` ``. Root `@skip`/`@include` are Condition nodes evaluated at execute. No stitch-side percent special-case. `backboneExecutor(request, schema?)` uses the arg else `request.info.schema`.
