# Apollo Router

**Apollo Router** is a **peer** <ConceptRef name="gateway">gateway</ConceptRef> to Hive Gateway in
the Mesh Serve Supergraph section (equal nav weight). Use it when your composed SDL is
**<ConceptRef name="connectors">HTTP/REST Connectors</ConceptRef>-compatible**
(<DirectiveRef name="connect" /> / <DirectiveRef name="source" /> on connect/v0.4-style emit).

## Honest limits

- Stock Apollo Router does **not** run Mesh <DirectiveRef name="sql" />,
  <DirectiveRef name="protobuf__rpc" />, SOAP, or other non-Connect Mesh transports.
- For multi-protocol Music Store Example graphs, run the **full** supergraph on Hive Gateway;
  dual-run the Connect slice on Apollo Router when demonstrating compatibility.

## Dual-run

Compose once to GraphQL SDL, then execute the same file on Hive Gateway and Apollo Router when the
schema stays on Connect:

```bash
mesh-compose -o supergraph.graphql
# Hive Gateway
hive-gateway supergraph
# Apollo Router (Connect-compatible SDL only)
./router --supergraph supergraph.graphql
```

FHIR (`e2e/json-schema-fhir`) is a Connect-compatible how-we-built that dual-runs. In the
[Music Store Example](/v2/examples/music-store), dual-run the **Reviews** slice after stage 2 -- not
the full SQL + gRPC graph.

Upstream Connect mapping:
[HTTP/REST Connectors reference](https://www.apollographql.com/docs/graphos/connectors/reference/directives).
