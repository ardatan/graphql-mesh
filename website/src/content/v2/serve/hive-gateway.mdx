# Hive Gateway

**Hive Gateway** is the preferred gateway runtime for <ConceptRef name="mesh">Mesh</ConceptRef>. In
Mesh docs it means the **JavaScript / TypeScript** <ConceptRef name="gateway">gateway</ConceptRef>.
It executes the full Mesh transport surface (HTTP/REST Connectors, SQL, Mongo, Protobuf, Thrift,
Neo4j, ...).

## When to use it

- Any Mesh-composed supergraph that uses non-Connect protocol directives
  (<DirectiveRef name="sql" />, <DirectiveRef name="protobuf__rpc" />,
  <DirectiveRef name="mongo" />, ...).
- Connect-compatible supergraphs (alongside or instead of Apollo Router).
- Serving a Mesh subgraph as a <ConceptRef name="federation">Federation</ConceptRef> subgraph behind
  another router -- see [Serve Subgraph](/v2/serve-subgraph).

## Compose, then serve

Same `mesh.config.ts` can export compose + gateway config. Register Mesh transports the supergraph
needs:

```ts
import { defineConfig as defineComposeConfig } from '@graphql-mesh/compose-cli'
import { defineConfig as defineGatewayConfig } from '@graphql-hive/gateway'
import { loadSqlSubgraph } from '@omnigraph/sql'

export const composeConfig = defineComposeConfig({
  subgraphs: [
    {
      sourceHandler: loadSqlSubgraph('chinook', {
        endpoint: 'file:chinook.db'
      })
    }
  ]
})

export const gatewayConfig = defineGatewayConfig({
  transports: {
    sql: import('@graphql-mesh/transport-sql')
    // protobuf: import('@graphql-mesh/transport-protobuf'),
    // mongo: import('@graphql-mesh/transport-mongo'),
  }
})
```

```bash
mesh-compose -o supergraph.graphql
hive-gateway supergraph
```

HTTP/REST Connectors often need no extra transport entry (Connect is built in). Register
`transport-protobuf` (and other Mesh protocol transports) only when the supergraph stamps those
kinds.

## Use cases

Register only the transports your supergraph actually stamps. A mixed Music Store graph needs SQL
and protobuf; Connect needs no extra entry. Thrift TJSON is Connect, so it does not load
`transport-thrift`. OpenAPI callback / JSON Schema webhook subscriptions need `webhooks: true` when
fields use `@pubsubOperation` / `@resolveTo` with `webhook:...` topics. For multi-instance EDFS,
pass a shared `pubsub` broker -- see [Subscriptions and pubsub](/v2/guides/subscriptions-pubsub):

```ts
export const gatewayConfig = defineGatewayConfig({
  // Music Store: SQL catalog + gRPC recommendations (Connect Reviews is built in)
  transports: {
    sql: import('@graphql-mesh/transport-sql'),
    protobuf: import('@graphql-mesh/transport-protobuf')
    // thrift: only for binary @thrift__rpc -- omit for TJSON @connect
  },
  // OpenAPI callback / webhook subscription fields
  webhooks: true
})
```

## In the Music Store Example

After all three stages, serve the **full** SQL + Connect + protobuf supergraph on Hive Gateway.
Dual-run only the Connect Reviews slice on [Apollo Router](/v2/serve/apollo-router). See
[Music Store Example](/v2/examples/music-store).
