# Composition

<ConceptRef name="composition">Composition</ConceptRef> via **Mesh Compose** turns subgraph
definitions into subgraph or supergraph GraphQL SDL -- the same path for loader emit and
hand-written files.

## Config shape

Typical `mesh.config.ts`:

- `subgraphs` entries with a `sourceHandler` (loader) **or** a hand-written `schema` file / SDL
  string.
- Shared options: optional [transforms](/v2/transforms), additional type defs, output mode
  (`graphql` / binary formats as supported).
- Optional `ignoreSemanticConventions` (see below).

```ts
import { defineConfig as defineComposeConfig } from '@graphql-mesh/compose-cli'
import { loadSqlSubgraph } from '@omnigraph/sql'
import { loadOpenAPISubgraph } from '@omnigraph/openapi'

export const composeConfig = defineComposeConfig({
  subgraphs: [
    {
      sourceHandler: loadSqlSubgraph('catalog', {
        endpoint: 'file:chinook.db'
      })
    },
    {
      sourceHandler: loadOpenAPISubgraph('reviews', {
        source: './openapi.json',
        endpoint: 'http://localhost:4001'
      })
    },
    {
      name: 'referenceResource',
      schema: './reference-resource.graphql'
    }
  ]
})
```

Compose to a file, then serve:

```bash
mesh-compose -o supergraph.graphql
```

Generated and hand-written subgraphs share the same compose and
[schema registry](/v2/concepts/schema-registry) path. Transforms are optional -- skip them when
Hand-write or Generate-then-edit already owns the SDL.

## Hand-written SDL

```ts
{
  name: 'referenceResource',
  schema: './reference-resource.graphql',
}
```

Use this for join-only subgraphs, fully authored Connect SDL, and edited loader output. FHIR's
`reference-resource.graphql` is the canonical join-only example.

## Semantic conventions (ById / ByIds)

During composition, Mesh applies **loader / Query semantic conventions** unless you opt out. When
the same object type appears across subgraphs and a Query field matches a ById / ByIds naming
pattern with a key arg that lines up with a key field on that type, Compose stamps Federation entity
wiring automatically -- `@key` plus Connect/protocol `entity: true` (or type-level `$this` maps),
instead of Mesh <DirectiveRef name="merge" /> on HTTP/REST Connectors subgraphs. Non-Connect Mesh
subgraphs may still receive `@merge` for type merging.

Naming is matched in snake_case. Typical patterns (key field often `id`):

| Field / arg (examples)                                 | Intent                 | Connect / protocol result                                                               |
| ------------------------------------------------------ | ---------------------- | --------------------------------------------------------------------------------------- |
| `Query.bookById` / `Query.bookById(id:)`               | Singular ById          | `entity: true` (or type-level `$this` / `@merge`)                                       |
| `Query.getCustomer` / `Query.getCustomer(id:)`         | `get_<Type>` + key arg | Same (`e2e/openapi-entity-stubs`)                                                       |
| `Query.getCustomerById` / `Query.getCustomerById(id:)` | Explicit ById suffix   | Same                                                                                    |
| `Query.customer` / `Query.customer(id:)`               | Type name + key arg    | Same                                                                                    |
| `Query.customersByIds` / `Query.customersByIds(ids:)`  | Batch ByIds            | Batch merge / batch Connect (no singular `_entities` claim without a singular resolver) |
| `Query.getFoosByIds` / `Query.getFoosByIds(ids:)`      | Batch with `get_`      | Same                                                                                    |

Repo anchors: `e2e/semantic-conventions` (`Query.bookById`), `e2e/openapi-entity-stubs`
(`Query.getCustomer` + `entity: true`).

If your schema almost matches but names differ, use a
[rename / naming-convention transform](/v2/transforms) so the field fits the convention -- or stamp
entities yourself with `createFederationTransform` (see
[Federation](/v2/concepts/federation#entity-resolution)).

Disable with `ignoreSemanticConventions: true` on the compose config when you want full manual
control (`e2e/semantic-conventions/mesh.config.conventions-disabled.ts`):

```ts
export const composeConfig = defineComposeConfig({
  ignoreSemanticConventions: true,
  subgraphs: [
    // ...
  ]
})
```

## Registry publish

Publish composed **subgraph** SDL to Hive schema registry / GraphOS with the same CLI UX whether the
SDL came from a loader or a file. See [Schema registry](/v2/concepts/schema-registry).

Worked multi-subgraph config: [Music Store Example](/v2/examples/music-store) (catalog + reviews +
recommendations, then compose all). Serve: [Serve Supergraph](/v2/serve).
