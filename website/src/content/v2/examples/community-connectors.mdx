<Callout type="info">
  Supporting example -- **not** the getting-started kickoff. Prefer [Music Store

[connectors-community](https://github.com/apollographql/connectors-community) publishes working
`@connect` / `@source` schemas (JSONPlaceholder, Stripe, Google Maps, ...). Mesh already vendors
several under the Connect transport test fixtures. You can drop the same SDL into Mesh Compose and
dual-run on **Hive Gateway** and **Apollo Router**.

## What you end up with

| Piece     | Detail                                                               |
| --------- | -------------------------------------------------------------------- |
| Source    | Public JSONPlaceholder REST (`https://jsonplaceholder.typicode.com`) |
| Authoring | Hand-checked community `.graphql` (or copy from the fixture)         |
| Dual-run  | Hive Gateway **and** Apollo Router (Connect-compatible)              |
| No Rover  | Mesh Compose + Hive Gateway is enough for local serve                |

## Compose community SDL

Point a subgraph at the `.graphql` file (same hand-write Compose path as Music Store stage 3):

```ts
import { defineConfig as defineComposeConfig } from '@graphql-mesh/compose-cli'

export const composeConfig = defineComposeConfig({
  subgraphs: [
    {
      name: 'jsonplaceholder',
      schema: './jsonplaceholder-users.graphql'
    }
  ]
})
```

Minimal excerpt (full fixture lives in the Mesh Connect transport tests /
`JSONPlaceholder/users.graphql`):

{/* prettier-ignore */}
```graphql
extend schema
  @link(url: "https://specs.apollo.dev/federation/v2.10", import: ["@key"])
  @link(url: "https://specs.apollo.dev/connect/v0.2", import: ["@connect", "@source"])
  @source(name: "JSONPlaceholder", http: { baseURL: "https://jsonplaceholder.typicode.com/" })

type User @key(fields: "id") {
  id: ID!
  name: String
  username: String
  email: String
}

type Query {
  getUser(id: ID!): User
    @connect(
      source: "JSONPlaceholder"
      http: { GET: "/users/{$args.id}" }
      selection: """
        id
        name
        username
        email
      """
      entity: true
    )
}
```

```bash
mesh-compose -o supergraph.graphql
hive-gateway supergraph
```

Same `supergraph.graphql` can dual-run on [Apollo Router](/v2/serve/apollo-router) when you stay on
stock Connect (no `@sql` / `@protobuf__rpc` / SOAP beside it).

## Use cases

### Prove dual-run with a public API

JSONPlaceholder needs no API key. Compose, query `getUser(id: "1")` on Hive Gateway, then point
Apollo Router at the same supergraph file for a Connect-only smoke.

### Bring another community connector

Copy a connectors-community schema (Stripe, USGS, ...), swap secrets into `@source` headers or
`operationHeaders` via env interpolation, and keep Mesh Compose as the composer. Prefer fixtures
that use recreatable endpoints -- same bar as the community repo.

### After Music Store Connect slice

When Reviews `@connect` is working, community schemas are optional next steps for richer Connect
vocabulary -- selection, entity, errors -- without changing Mesh product identity. See
[Selection mapping](/v2/guides/selection-mapping) and
[Directives: @connect](/v2/directives#connect).
