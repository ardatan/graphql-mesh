# Reading generated SDL

Generated <ConceptRef name="mesh">Mesh</ConceptRef> subgraphs are ordinary GraphQL SDL with
directives. Before you edit or hand-write, learn to recognize the important stamps. This page is a
**reading guide** -- for arg tables see the [Directives reference](/v2/reference/directives) and

<ConceptRef name="connectors">HTTP/REST Connectors</ConceptRef> upstream. How we name one type,
field, arg, or directive: [Schema Coordinates](/v2/guides/schema-coordinates) (Spec `Type.field`,
`Type.field(arg:)`, ...).

## What to look for

| Piece                                                                   | Meaning                                                                                                                                                    | Dig deeper                                                                                                                                                        |
| ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| <DirectiveRef name="transport" />                                       | Which Mesh transport executes this subgraph at the gateway.                                                                                                | [Directives](/v2/reference/directives#transport) / [Architecture](/v2/architecture)                                                                               |
| <DirectiveRef name="connect" /> / <DirectiveRef name="source" />        | HTTP/REST Connectors-style mapping (Router dual-run when compatible).                                                                                      | [Directives](/v2/reference/directives#connect) / [Apollo's HTTP Connectors reference](https://www.apollographql.com/docs/graphos/connectors/reference/directives) |
| Protocol directives                                                     | <DirectiveRef name="sql" />, <DirectiveRef name="mongo" />, <DirectiveRef name="thrift__rpc" />, <DirectiveRef name="protobuf__rpc" />, Neo4j natives, ... | [Directives](/v2/reference/directives) / [Protocols](/v2/protocols)                                                                                               |
| <DirectiveRef name="key" />                                             | <ConceptRef name="federation">Federation</ConceptRef> entity key; often `resolvable: false` on join stubs.                                                 | [Directives](/v2/reference/directives#federation) / [Entity resolution](/v2/concepts/federation#entity-resolution)                                                |
| <DirectiveRef name="merge" /> / <DirectiveRef name="resolveTo" />       | Mesh type-merging / field delegation (prefer `@key` + Connect or protocol entity maps for new work).                                                       | [Directives](/v2/reference/directives#merge) / [Directives](/v2/reference/directives#resolveTo)                                                                   |
| `entity: true` / type-level entity maps                                 | Wires `_entities` / `resolveReference` for Connect or protocol lookups.                                                                                    | [Federation](/v2/concepts/federation#entity-resolution) / [Semantic conventions](/v2/compose#semantic-conventions)                                                |
| `selection` / `args`                                                    | How JSON (or rows) map into GraphQL fields and how field args become HTTP / RPC inputs.                                                                    | [Selection mapping](/v2/guides/selection-mapping) / [Apollo mapping](https://www.apollographql.com/docs/graphos/connectors/mapping)                               |

## Conventions that help

1. Start from a **root field** you already queried (coordinate `Query.<field>`), then follow its
   `@connect` / protocol directive.
2. Trace `$args` and `$this` in `selection` before renaming anything -- see
   [Selection mapping](/v2/guides/selection-mapping). Name the GraphQL arg with Spec form
   `Type.field(arg:)` when you talk about it outside binders.
3. Treat emitted SDL as the contract you will either keep, edit, or rewrite by hand.
4. Prefer [Schema Coordinates](/v2/guides/schema-coordinates) for unique element ids; keep Mesh
   **schema selectors** (`Query.*`, filter globs) labeled as selectors, not Spec coordinates.
