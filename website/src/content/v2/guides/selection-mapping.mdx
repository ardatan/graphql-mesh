# Selection mapping

Most Mesh protocol directives carry a **request map** and a **response map**. Authors see them as
`args` / `where` / `http` binders on the way **out**, and `selection` on the way **back** into
GraphQL fields. Loaders emit these strings; [Hand-write](/v2/paths/hand-write) and
[Generate-then-edit](/v2/paths/generate-then-edit) edit the same shapes.

This guide is the shared mental model. Per-directive args live on the
[Directives reference](/v2/reference/directives). Deep Connect / JSONSelection syntax is upstream:
[Apollo Connectors mapping](https://www.apollographql.com/docs/graphos/connectors/mapping).

## Two directions

| Direction      | Typical args                      | Meaning                                                               |
| -------------- | --------------------------------- | --------------------------------------------------------------------- |
| GraphQL → wire | `args`, `where`, `http`, `set`, … | Field arguments and parent fields become HTTP / SQL / RPC / doc input |
| Wire → GraphQL | `selection`                       | JSON, rows, protobuf fields, or documents become GraphQL fields       |

Both sides use the same binder vocabulary (`$args`, `$this`, …). Trace those binders before you
rename fields or rewrite a mapping.

## Binders you will see

| Binder     | Meaning                                                         |
| ---------- | --------------------------------------------------------------- |
| `$args`    | Arguments on the GraphQL field being resolved                   |
| `$this`    | Fields already selected on the parent / entity object           |
| `$batch`   | Batched entity keys (Connect batch / entity resolvers)          |
| Path forms | `$args.id`, `$this.TrackId`, nested objects / lists per dialect |

Exact operators (`->split`, `->match`, `->get`, …) are part of **Connect JSONSelection**. SQL /
Mongo / Protobuf dialects reuse `$args` / `$this` but not the full Apollo expression language.

## Connect HTTP (`selection` + URL / body)

<DirectiveRef name="connect" /> maps HTTP responses with Apollo-style `selection`, and puts path /
query / body binders in `http` (and related args):

```graphql
type Track @key(fields: "id", resolvable: false) {
  id: ID!
  reviews: [Review!]
    @connect(
      source: "reviews"
      http: { GET: "/reviews?trackId={$this.id}" }
      selection: """
      id
      rating
      body
      """
    )
}
```

- `{$this.id}` in the URL is the **request** side (parent entity key).
- The `selection` block is the **response** side (JSON keys → GraphQL fields).
- Entity / batch patterns add `$batch` and `entity: true` -- see Apollo's mapping docs.

Mesh OpenAPI / JSON Schema / OData (and SOAP-as-Connect) loaders emit this shape. Dual-run Connect
SDL on [Hive Gateway](/v2/serve/hive-gateway) and [Apollo Router](/v2/serve/apollo-router).

## SQL (`where` / `args` + `selection`)

SQL emit uses <DirectiveRef name="sql" /> (kind discriminator: `ROW` / `ROWS` / `CONNECTION` /
`COUNT` / `INSERT` / `UPDATE` / `DELETE`). Request binders land in `where` / structured `args`;
column maps land in `selection`:

```graphql
type Query {
  track(id: ID!): Track
    @sql(
      table: "Track"
      kind: ROW
      where: """
      TrackId: $args.id
      """
      selection: """
      TrackId
      Name
      AlbumId
      """
      entity: true
    )
}
```

Relations and type-level entity fills use `$this` the same way Connect does (`AlbumId: $this.id`).
Hive Gateway only -- stock Apollo Router does not execute `@sql`.

## Protobuf / gRPC (`args` + `selection`)

<DirectiveRef name="protobuf__rpc" /> uses a **compact field-number** dialect (not JSONSelection):

```graphql
type Query {
  recommendation(trackId: ID!): Recommendation!
    @protobuf__rpc(
      service: "Recommendations"
      method: "GetRecommendation"
      args: """
      1(string): $args.trackId
      """
      selection: """
      1(string): id
      2(string): trackId
      """
    )
}
```

- `args`: GraphQL → protobuf request (`N(type): binder`).
- `selection`: protobuf response → GraphQL fields.
- Nested messages use `{ … }` blocks; repeated fields use `repeated` in the type slot.

Thrift binary (`@thrift__rpc`) follows the same **args / selection / throws** idea with Thrift
types. See [Protocols](/v2/protocols).

## Mongo and Neo4j

- **Mongo:** op-specific `@mongo__*` binders (`query` / `where` / `set` / `selection`, …) under
  `https://specs.graphql-mesh.com/mongo/v0.1`. `$args` and `$this` still name GraphQL inputs and
  parent fields.
- **Neo4j:** native `@neo4j/graphql` directives (not a Mesh `selection` string dialect). Mesh stamps
  `@transport` + a neo4j `@link` for the subgraph; mapping lives in Neo4j's own Cypher / filter
  args.

## Habits that help

1. Start from one root field you already queried; read its directive top to bottom.
2. Circle every `$args` / `$this` (and `$batch`) before renaming GraphQL or wire fields.
3. Prefer editing `selection` / binders over inventing a new directive when the transport already
   fits.
4. After edits, re-compose and re-query -- the same habit as
   [Generate-then-edit](/v2/paths/generate-then-edit).
