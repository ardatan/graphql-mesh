# SQL

Use SQL when tables should become GraphQL types with **typed** query / mutation fields, FK
navigation, and Federation `@key` entity fill -- without wrapping the DB in REST. This is a **Mesh
protocol** (not HTTP/REST Connectors). The loader emits <DirectiveRef name="sql" /> with a `kind`
discriminator; Hive Gateway runs `transport-sql`. Stock Apollo Router does **not** execute `@sql`.

| Piece     | Detail                                                                            |
| --------- | --------------------------------------------------------------------------------- |
| Loader    | `@omnigraph/sql` (`loadSqlSubgraph`)                                              |
| Directive | `@sql` (`ROW` / `ROWS` / `CONNECTION` / `COUNT` / `INSERT` / `UPDATE` / `DELETE`) |
| Transport | `@graphql-mesh/transport-sql`                                                     |
| Spec      | `https://specs.graphql-mesh.dev/sql/v0.1`                                         |
| Dual-run  | Hive Gateway; Apollo Router via [Serve Subgraph](/v2/serve-subgraph)              |
| Examples  | Chinook (SQLite); Music Store stage 1; MySQL / Postgres                           |

## Packages

```bash
pnpm add @graphql-mesh/compose-cli @omnigraph/sql @graphql-hive/gateway @graphql-mesh/transport-sql
# npm i @graphql-mesh/compose-cli @omnigraph/sql @graphql-hive/gateway @graphql-mesh/transport-sql
```

## Generate Chinook

```ts
import { defineConfig as defineComposeConfig } from '@graphql-mesh/compose-cli'
import { loadSqlSubgraph } from '@omnigraph/sql'

export const composeConfig = defineComposeConfig({
  subgraphs: [
    {
      sourceHandler: loadSqlSubgraph('chinook', {
        endpoint: 'file:chinook.db'
      })
    }
  ]
})
```

## Single row + entity fill

Query by primary key (`kind: ROW` + `$args`). The object type repeats `ROW` with `$this` so
Federation can resolve the entity:

{/* prettier-ignore */}
```graphql
extend schema
  @link(url: "https://specs.graphql-mesh.dev/sql/v0.1", import: ["@sql"])
  @link(url: "https://specs.graphql-mesh.dev/core/v0.1", import: ["@transport"])

schema @transport(subgraph: "chinook", kind: "sql", location: "file:chinook.db") {
  query: Query
}

type Query {
  album(id: ID!): Album
    @sql(
      table: "albums"
      kind: ROW
      where: """
        AlbumId: $args.id
      """
      selection: """
        id: AlbumId
        title: Title
        artistId: ArtistId
      """
    )
}

type Album
  @key(fields: "id")
  @sql(
    table: "albums"
    kind: ROW
    where: """
      AlbumId: $this.id
    """
    selection: """
      id: AlbumId
      title: Title
      artistId: ArtistId
    """
  ) {
  id: ID!
  title: String!
  artistId: Int!
}
```

## FK navigation and lists

Child collections use `kind: ROWS` with `$this` plus optional `$args.where` (Artist -> albums).
Many-to-many uses `through:` (Playlist -> tracks via `playlist_track` in Chinook):

{/* prettier-ignore */}
```graphql
type Artist @key(fields: "id") {
  id: ID!
  name: String
  albums(where: AlbumFilter, orderBy: [AlbumOrderBy!], limit: Int, offset: Int): [Album!]!
    @sql(
      table: "albums"
      kind: ROWS
      where: """
        ArtistId: $this.id
        ...$args.where
      """
      orderBy: "$args.orderBy"
      limit: "$args.limit"
      offset: "$args.offset"
      selection: """
        id: AlbumId
        title: Title
        artistId: ArtistId
      """
    )
}

type Playlist {
  tracks(where: TrackFilter, limit: Int, offset: Int): [Track!]!
    @sql(
      table: "tracks"
      kind: ROWS
      through: """
      table: playlist_track
      local: PlaylistId
      remote: TrackId
      parent: $this.id
      target: TrackId
      """
      where: "$args.where"
      limit: "$args.limit"
      offset: "$args.offset"
      selection: """
        id: TrackId
        name: Name
      """
    )
}
```

`albums(...)` list roots, `allAlbums` connections (`kind: CONNECTION`), and `albumsCount`
(`kind: COUNT`) follow the same table / selection dialect.

## Mutations

`INSERT` / `UPDATE` / `DELETE` bind columns from `$args`:

{/* prettier-ignore */}
```graphql
type Mutation {
  createAlbum(input: CreateAlbumInput!): AlbumPayload!
    @sql(
      table: "albums"
      kind: INSERT
      set: """
      Title: $args.input.title
      ArtistId: $args.input.artistId
      """
      selection: """
        album {
          id: AlbumId
          title: Title
          artistId: ArtistId
        }
      """
    )

  deleteAlbum(id: ID!): DeleteAlbumPayload!
    @sql(
      table: "albums"
      kind: DELETE
      where: """
        AlbumId: $args.id
      """
      selection: """
        ok: $affectedRows
        affectedRows: $affectedRows
      """
    )
}
```

In `selection`, the loader maps **original SQL columns to GraphQL fields** (e.g. `id: TrackId`,
`name: Name`). `where` / `set` keep referring to those SQL columns (`TrackId: $args.id`). That
column-to-field mapping is the loader concern -- not a separate "rename everything to camelCase"
rule. Binders: [Selection mapping](/v2/guides/selection-mapping). Entity / ById:
[Composition semantic conventions](/v2/compose#semantic-conventions).

## Use cases

### Cursor connection + count

Offset lists (`kind: ROWS`) are not the only list shape. `CONNECTION` builds Relay-style `nodes` /
`pageInfo` / `$totalCount` from the same table; `COUNT` returns a scalar:

{/* prettier-ignore */}
```graphql
type Query {
  allAlbums(
    where: AlbumFilter
    orderBy: [AlbumOrderBy!]
    first: Int
    after: String
  ): AlbumConnection!
    @sql(
      table: "albums"
      kind: CONNECTION
      where: "$args.where"
      orderBy: "$args.orderBy"
      first: "$args.first"
      after: "$args.after"
      selection: """
        nodes {
          id: AlbumId # SQL AlbumId -> GraphQL id
          title: Title
        }
        pageInfo {
          hasNextPage: $hasNextPage
          endCursor: $endCursor
        }
        totalCount: $totalCount
      """
    )

  # Scalar count with the same where binder
  albumsCount(where: AlbumFilter): Int!
    @sql(table: "albums", kind: COUNT, where: "$args.where", selection: "$")
}
```

### FK `$this` plus client filters

Related lists pin the parent key with `$this`, then splice in optional client filters via
`...$args.where` so callers can still page or filter the related set:

{/* prettier-ignore */}
```graphql
type Artist @key(fields: "id") {
  id: ID!
  albums(where: AlbumFilter, limit: Int, offset: Int): [Album!]!
    @sql(
      table: "albums"
      kind: ROWS
      where: """
        ArtistId: $this.id # always constrain to this artist
        ...$args.where # optional client filter merged in
      """
      limit: "$args.limit"
      offset: "$args.offset"
      selection: """
        id: AlbumId
        title: Title
      """
    )
}
```

### Many-to-many `through`

When there is no direct FK on the target table, `through` describes the join table. Playlist tracks
go through `playlist_track`: `local` is the parent column, `remote` / `target` reach `tracks`:

{/* prettier-ignore */}
```graphql
type Playlist {
  tracks(where: TrackFilter, limit: Int, offset: Int): [Track!]!
    @sql(
      table: "tracks"
      kind: ROWS
      through: """
      table: playlist_track
      local: PlaylistId # column on join table for this Playlist
      remote: TrackId # column on join table toward tracks
      parent: $this.id
      target: TrackId # PK on tracks
      """
      where: "$args.where"
      limit: "$args.limit"
      offset: "$args.offset"
      selection: """
        id: TrackId
        name: Name
      """
    )
}
```
