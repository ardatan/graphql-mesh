# Mongo

Use Mongo when collections should become GraphQL types with **find / filter / aggregate / CRUD**
ops, ObjectId keys, and Federation entity fill -- without inventing a REST facade. This is a **Mesh
protocol** (not HTTP/REST Connectors). The loader stamps `@mongo__*` ops; Hive Gateway runs
`transport-mongo`. Stock Apollo Router does **not** execute them.

| Piece         | Detail                                                                   |
| ------------- | ------------------------------------------------------------------------ |
| Loader        | `@omnigraph/mongo` (`loadMongoSubgraph`)                                 |
| Directives    | `@mongo__findOne`, `@mongo__find`, CRUD, ...                             |
| Transport     | `@graphql-mesh/transport-mongo`                                          |
| Spec          | `https://specs.graphql-mesh.dev/mongo/v0.1`                              |
| Apollo Router | Via [Serve Subgraph](/v2/serve-subgraph) (Hive Gateway runs `@mongo__*`) |
| Examples      | Mongoose users model                                                     |

## Packages

```sh npm2yarn
npm i @graphql-mesh/compose-cli @omnigraph/mongo @graphql-hive/gateway @graphql-mesh/transport-mongo
```

## Generate from a Mongoose model

```ts
import { defineConfig } from '@graphql-mesh/compose-cli'
import { loadMongoSubgraph } from '@omnigraph/mongo'

export const composeConfig = defineConfig({
  subgraphs: [
    {
      sourceHandler: loadMongoSubgraph('Mongoose', {
        endpoint: 'mongodb://127.0.0.1:27017/mesh_users',
        models: [{ name: 'User', path: './src/models.js#User' }]
      })
    }
  ]
})
```

## Find by id and entity fill

Query `findUserById` uses `$args`; type-level `@mongo__findOne` uses `$this` for Federation:

{/* prettier-ignore */}
```graphql
extend schema
  @link(
    url: "https://specs.graphql-mesh.dev/mongo/v0.1"
    import: ["@mongo__findOne", "@mongo__find", "@mongo__insertOne"]
  )
  @link(url: "https://specs.graphql-mesh.dev/core/v0.1", import: ["@transport"])

schema @transport(subgraph: "users", kind: "mongo", location: "mongodb://localhost:27017/test") {
  query: Query
}

type Query {
  findUserById(id: ObjectID!): User
    @mongo__findOne(
      collection: "user_users"
      query: """
      _id: $args.id
      """
      selection: """
        id: _id
        name: name
        age: age
      """
    )

  findUsers(filter: UserFilterInput, sort: [UserSort!], limit: Int = 100, skip: Int): [User!]!
    @mongo__find(
      collection: "user_users"
      query: "$args.filter"
      sort: "$args.sort"
      limit: "$args.limit"
      skip: "$args.skip"
      selection: """
        id: _id
        name: name
        age: age
      """
    )
}

type User
  @key(fields: "id")
  @mongo__findOne(
    collection: "user_users"
    query: """
    _id: $this.id
    """
    selection: """
      id: _id
      name: name
      age: age
    """
  ) {
  id: ObjectID!
  name: String
  age: Float
}
```

## Mutations

{/* prettier-ignore */}
```graphql
type Mutation {
  insertOneUser(document: UserDocumentInput!): User
    @mongo__insertOne(
      collection: "user_users"
      set: "$args.document"
      selection: """
        id: _id
        name: name
      """
    )

  updateUserById(id: ObjectID!, update: UserUpdateInput!): User
    @mongo__updateOne(
      collection: "user_users"
      query: """
      _id: $args.id
      """
      set: "$args.update"
      selection: """
        id: _id
        name: name
      """
    )
}
```

## Use cases

### Batch ByIds

Beside singular `findUserById`, batch lookup passes an id list into `_id`. Federation / entity
batching can use this when many parents need the same collection filled at once:

{/* prettier-ignore */}
```graphql
type Query {
  findUsersByIds(ids: [ObjectID!]!, limit: Int = 100, sort: [UserSort!]): [User!]!
    @mongo__find(
      collection: "user_users"
      query: """
      _id: $args.ids # list of ObjectIds -> $in-style find
      """
      limit: "$args.limit"
      sort: "$args.sort"
      selection: """
        id: _id # Mongo _id -> GraphQL id
        name: name
      """
    )
}
```

### Aggregate + connection

`@mongo__aggregate` forwards a client `pipeline` JSON; `@mongo__connection` is the cursor-style list
companion to offset `find`:

{/* prettier-ignore */}
```graphql
type Query {
  # Pass-through aggregation stages from the client
  aggregateUsers(filter: UserFilterInput, pipeline: JSON): [JSON!]!
    @mongo__aggregate(
      collection: "user_users"
      query: "$args.filter"
      pipeline: "$args.pipeline"
      selection: "$" # raw aggregate documents
    )

  findUsersConnection(
    filter: UserFilterInput
    sort: [UserSort!]
    first: Int
    after: String
  ): UserConnection
    @mongo__connection(
      collection: "user_users"
      query: "$args.filter"
      sort: "$args.sort"
      first: "$args.first"
      after: "$args.after"
      selection: """
        nodes {
          id: _id
          name: name
        }
      """
    )
}
```

### ObjectId / Decimal128 / mixed JSON

Models with ObjectId keys, Decimal128 money fields, or schemaless blobs emit GraphQL scalars such as
`ObjectID`, `Decimal128`, and `JSON`. Transport options may list which collection fields are
ObjectIds (`objectIdFieldsByCollection`) so the executor coerces correctly.
