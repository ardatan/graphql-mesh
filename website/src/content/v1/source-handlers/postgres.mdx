# PostgreSQL

Use `@omnigraph/sql` with `type: 'postgres'`. Same `@sql__*` author surface as MySQL/SQLite; dialect
differences stay in SQL generation and introspection.

```sh npm2yarn
npm i @omnigraph/sql
```

```ts filename="mesh.config.ts"
import { defineConfig } from '@graphql-mesh/compose-cli'
import { loadSqlSubgraph } from '@omnigraph/sql'

export const composeConfig = defineConfig({
  subgraphs: [
    {
      sourceHandler: loadSqlSubgraph('GeoDB', {
        type: 'postgres',
        connectionString: 'postgres://postgres:password@localhost/postgres'
      })
    }
  ]
})
```

<Callout type="warning">
  Postgres introspection/execute is landing behind sqlite/mysql in the SQL directives stack. The
  loader API and directive surface are shared; prefer sqlite/mysql today if you need a green path
  immediately.
</Callout>

<Callout type="info">
  This replaces the never-shipped `@omnigraph/postgresql` promise and the legacy
  `@graphql-mesh/postgraphile` handler. There is no PostGraphile runtime dependency on the new path.
</Callout>
