## Frequently Asked Questions

- What is GraphQL Mesh?

  GraphQL Mesh is a **Federation Framework for any API**. You generate (or hand-write)
  Federation-ready Mesh subgraph SDL from GraphQL and non-GraphQL sources -- REST / OpenAPI, SQL,
  gRPC, and more -- then compose and serve. Mesh is **platform / registry / gateway independent**:
  keep GraphOS, Hive, Rover, or any Federation-compatible stack. [Mesh v2 introduction](/v2).

- Already have Federation: why Mesh?

  Use Mesh when you need **non-GraphQL sources as Federation subgraphs** without replacing Router,
  GraphOS, Hive Gateway, or your registry. Generate subgraph SDL, optionally transform it, compose
  with your existing GraphQL subgraphs, and drop the Mesh peers into the gateway you already run.
  Mesh uses **Connectors** natively in Apollo Router and Hive Gateway; non-Connect protocols (SQL,
  etc.) still work on Apollo Router by serving the subgraph separately
  ([`buildSubgraphSchema`](/v2/guides/build-subgraph-schema) / Hive subgraph serve).
  [FAQ: why Mesh](/v2/faq#already-have-federation-why-mesh).

- New to Federation: why Mesh?

  Mesh **generates Federation-ready subgraphs** from the APIs and databases you already have, so you
  do not have to hand-author every directive to get a first working graph. Compose with Mesh Compose
  (or a registry), then **run with any Federation Gateway**. Connectors run natively on Hive Gateway
  and Apollo Router; non-Connect protocols use Hive Gateway on the supergraph or a served Mesh
  subgraph peer. [FAQ: new to Federation](/v2/faq#new-to-federation-why-mesh).

- How do I go from a source to a running graph?

  **Generate** subgraph SDL → optional **Transform** → **Serve Subgraph** when another gateway needs
  a Mesh-backed Federation URL → **Compose** → **Gateway**. Authoring paths:
  [Generate](/v2/paths/generate), [Generate-then-edit](/v2/paths/generate-then-edit),
  [Hand-write](/v2/paths/hand-write). Serve: [Serve Supergraph](/v2/serve) /
  [Serve Subgraph](/v2/serve-subgraph) / [`buildSubgraphSchema`](/v2/guides/build-subgraph-schema).

- Can Mesh enhance an existing Federation setup?

  Yes. Mesh **enhances** the Federation graph you already operate -- it does not require a stack
  swap. Keep Apollo GraphOS + Router, Hive Gateway + Registry, or any other Federation-compatible
  gateway; add Mesh-generated (or authored) subgraphs beside your GraphQL peers, recompose, and
  continue serving on the same gateway.
  [Enhance an existing Federation](/v2#enhance-an-existing-federation) /
  [FAQ: drop-in](/v2/faq#can-mesh-drop-into-an-existing-federation-setup).

- Where can Mesh run?

  **Hive Gateway** across any JS environment (Node.js, Bun, Docker, serverless), **Apollo Router**
  (Rust) with Connectors native in both, **any Federation Gateway** for composed SDL, and a Mesh
  subgraph process on Yoga or any GraphQL server via
  [`buildSubgraphSchema`](/v2/guides/build-subgraph-schema) from `@graphql-mesh/subgraph` -- same
  Federation wiring job as Apollo's `buildSubgraphSchema`, plus Mesh directive / Mesh specification
  execution (including non-Connect protocols behind Apollo Router). [Serve Supergraph](/v2/serve) /
  [Hive Gateway](/v2/serve/hive-gateway) / [Apollo Router](/v2/serve/apollo-router).
